## Description

As a ResumeEnhancer guest, user, administrator, or platform operator, I want authentication and authorization enforced consistently with secure account recovery and password controls, so that public discovery remains available while private data and privileged operations are protected.

Add OWASP-aligned JWT authentication, fail-closed authorization, guest-access boundaries, and secure account/password lifecycle operations to AuthModule and WebSolution. The existing `/register`, `/refresh`, `/logout`, `/verify-email/resend`, and `/bootstrap` endpoints must remain in place and retain their current purpose. Frontend implementation is out of scope.

Scope includes login, standards-compliant JWT issuance and bearer validation, authentication before authorization, a fail-closed fallback policy with explicit anonymous allowlisting, role/capability/policy/resource-ownership authorization, principal-derived identity and audit actors, active/verified/non-disabled/non-locked account enforcement, password change and recovery flows, previous-two password history, refresh/session hardening, key management, distributed rate limits, redacted ProblemDetails, and structured security auditing.

## Acceptance Criteria

- Valid login creates a refresh-session family, issues a JWT access token, and returns a safe authentication response.
- Invalid, unknown, unverified, disabled, or locked login attempts do not reveal the account condition and do not create a session.
- Valid bearer tokens populate `HttpContext.User` before authorization; protected endpoints return `401` for missing/invalid tokens and `403` for insufficient authorization.
- Approved anonymous endpoints work without JWT while private, administrative, mutation, and ownership-protected operations remain protected.
- Client-provided identity headers cannot impersonate the authenticated subject or audit actor.
- Account status and email verification rules are enforced during login, refresh, and protected access.
- Password change/reset is transactional, history-checked, rate-limited, audited, and revokes applicable refresh sessions.
- Forgot-password responses do not reveal account existence; reset challenges are hashed, short-lived, single-use, and session-revoking.
- Existing refresh rotation, family reuse detection, expiry checks, and concurrent-use protection remain regression-safe.
- Key rotation uses the active key for new JWTs and validates approved previous keys only during configured overlap.
- Authentication-sensitive abuse returns safe throttling responses and audit events.
- Errors are standardized and redacted; sensitive credentials, tokens, secrets, inner exceptions, SQL details, and production stack traces are never exposed.
- Existing registration, refresh, logout, verification-resend, bootstrap, idempotency, consent, outbox, and atomic-registration tests continue to pass.
- Unit and integration tests cover JWT validation, guest access, policies, ownership, account states, password history, reset-token reuse, refresh replay, key rotation, rate limiting, CSRF, and error redaction.
