# Research — Resume Checker And Job Match Review Workspace

## Research Basis

The selected competitors position resume checking and job matching as decision-support tools. The most informative evidence comes from Novorésumé, which describes a 5-area ATS score and a 5-category job match in explicit detail. That structured taxonomy should directly inform our own analysis vocabulary. Resume Now adds a grammar/proofread dimension.

## Competitive Interpretation

- Analysis is productized as a **reportable outcome** with a structured breakdown, not a vague score.
- The 5-area ATS score and 5-category job match provide a concrete, adoptable taxonomy for our own analysis vocabulary.
- **"Honest, not flattering"** is a powerful positioning choice — it signals that the product will give truthful (even negative) feedback, which differentiates from over-scored competitors.
- The **two-tier funnel** (free quick check → email-gated detailed report) is a proven lead-acquisition pattern worth evaluating.
- Both competitors loop analysis results back into the builder for editing, making analysis part of an improvement cycle, not a standalone gimmick.

## Product Interpretation

- Analysis should be a structured report, not a single score widget.
- Categories must be named and explainable — the Novorésumé taxonomy is a strong model.
- General resume quality and job-specific match must be separate modes (or clearly differentiated report sections).
- The "honest" positioning is a trust differentiator if backed by transparent, actionable feedback.
- Two-tier (free summary / premium detail) and email-gating are both proven patterns; pick one and execute it cleanly.

## Hidden Requirements Inferred

- Version-linked analysis runs (stale results flagged after resume edits).
- Structured recommendation categories mapped to editable sections.
- Severity/priority levels for findings.
- Premium gating for depth (free gets summary/score; premium gets detailed recommendations).
- Privacy handling for standalone/no-signup tools (auto-delete, storage policy).

## ATS Score Category Map (Recommended)

| Category | What it checks | Example finding |
| --- | --- | --- |
| Job Match / Keywords | alignment with target job description | "Missing Python and SQL from job requirements" |
| Format & Structure | ATS-parseable layout | "Tables may break parsing; use single-column layout" |
| Content Quality | impact, specificity, clarity | "Bullet 3 lacks metrics; add a measurable result" |
| Section Organization | required sections present | "Missing Education section" |
| Technical Elements | special chars, encoding issues | "Em-dash character may not parse in some ATS" |

## Job Match Category Map (Recommended)

| Category | What it checks | Example finding |
| --- | --- | --- |
| Hard Requirements | years experience, certifications, degrees | "Job requires 3+ years; your resume shows 4" |
| Skills Alignment | technical and domain skills | "Strong match on React, Node.js; gap on TypeScript" |
| Seniority Fit | level/scope match | "Your senior-level experience exceeds the mid-level role" |
| Industry Match | domain context | "Fintech experience partially transfers to this banking role" |
| Career Trajectory | career-progression logic | "This role would be a lateral move based on your current title" |

## Risks If Under-Specified

- Designers may create a one-screen score widget with insufficient actionability.
- Engineers may blur general quality scoring and job-specific matching into confusing mixed output.
- Without stale-result detection, users may trust an outdated analysis after editing.
- If the analysis is falsely positive ("90% match" always), it loses credibility quickly — the "honest" positioning raises the bar.

## Recommendation To Developers

- Keep report data explicit and categorized.
- Treat the review workspace as an iteration loop: run → inspect → edit → rerun.
- Version-link each analysis run to the resume state at generation time.
- Distinguish fix-in-resume recommendations from fix-in-cover-letter recommendations (Novorésumé pattern).
- Build the two-tier free/paid detail split at the backend, surfaced by the frontend.

## Open Questions

- Should MVP combine ATS check and job match into one report or separate tabs?
- Should free users receive a summary score only while premium users receive detailed fixes (Novorésumé Quick vs. Complete pattern)?
- Email-gated detailed report (lead-gen funnel) — yes/no for our MVP?
- Should users be able to save multiple job descriptions per resume in later phases?
