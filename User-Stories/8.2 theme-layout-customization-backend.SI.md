# Supporting Information — Theme Customization And Layout Ordering Services

## Suggested Data Structures

The backend models a **tokenized appearance layer**: fonts, themes, and visual styles are referenced by stable IDs, not inline CSS. This enables safe theme switching, premium/ATS-safe enforcement, and render-engine consistency.

```ts
type CustomizationCapabilities = {
  templateId: string;
  fonts: Array<{
    id: string;
    name: string;
    category: "sans-serif" | "serif" | "monospace";
    isPremium: boolean;
    isAtsSafe: boolean;
  }>;
  colorThemes: Array<{
    id: string;
    name: string;
    primaryColor: string;      // hex
    accentColor: string;        // hex
    textColor: string;          // hex
    isPremium: boolean;
    isAtsSafe: boolean;         // false if contrast is too low for ATS readability
  }>;
  backgroundStyles?: Array<{
    id: string;
    name: string;
    previewUrl: string;
    isPremium: boolean;
    isAtsSafe: boolean;         // always false — blocked in ATS-safe mode
  }>;
  pictureStyles?: Array<{
    id: string;
    name: string;
    shape: "circle" | "rounded-square" | "standard";
    borderStyle: string;
    isPremium: boolean;
    isAtsSafe: boolean;
  }>;
  ratingStyles?: Array<{
    id: string;
    name: string;
    icon: "bars" | "dots" | "stars";
    isPremium: boolean;
    isAtsSafe: boolean;         // always false in ATS-safe mode — replaced with text
  }>;
  iconSets?: Array<{
    id: string;
    name: string;
    previewUrl: string;
    isPremium: boolean;
    isAtsSafe: boolean;         // always false in ATS-safe mode — replaced with text labels
  }>;
  layoutOrdering: {
    sectionReorder: boolean;    // free = false, premium = true
    itemReorder: boolean;       // free = false, premium = true
    isPremium: boolean;
  };
};

type DocumentCustomizationState = {
  documentId: string;
  schemaVersion: string;
  fontId: string;
  colorThemeId: string;
  backgroundStyleId?: string;
  pictureStyleId?: string;
  ratingStyleId?: string;
  iconSetId?: string;
  updatedAt: string;
};
```

## Suggested ResumeEnhancer.Infrastructure.Persistence Concepts

| Concept | Purpose | Storage |
| --- | --- | --- |
| `CustomizationCapabilitySet` | What a specific template supports for customization — derived from template metadata + product config | Cached in memory; derived from Template + Plan capabilities |
| `DocumentCustomizationState` | Active appearance choices for a document | SQL/JSON column |
| `DocumentLayoutOrder` | Persisted section and item sequence | SQL/JSON column |

## Example API Shapes

### `GET /documents/{id}/customization`

```json
{
  "capabilities": {
    "fonts": [
      { "id": "font_roboto", "name": "Roboto", "category": "sans-serif", "isPremium": false, "isAtsSafe": true },
      { "id": "font_lora", "name": "Lora", "category": "serif", "isPremium": true, "isAtsSafe": true }
    ],
    "colorThemes": [
      { "id": "theme_navy", "name": "Navy Professional", "primaryColor": "#1a365d", "textColor": "#ffffff", "isPremium": false, "isAtsSafe": true },
      { "id": "theme_forest", "name": "Forest Green", "primaryColor": "#2d6a4f", "textColor": "#ffffff", "isPremium": true, "isAtsSafe": true }
    ],
    "layoutOrdering": {
      "sectionReorder": false,
      "itemReorder": true,
      "isPremium": false
    }
  },
  "activeState": {
    "fontId": "font_roboto",
    "colorThemeId": "theme_navy",
    "pictureStyleId": null,
    "ratingStyleId": null,
    "schemaVersion": "1.0"
  },
  "entitlementContext": {
    "plan": "basic_free",
    "previewAllowed": true,
    "downloadAllowed": false
  }
}
```

### `PATCH /documents/{id}/customization`

Request:
```json
{
  "fontId": "font_lora",
  "colorThemeId": "theme_forest"
}
```

Response (success):
```json
{
  "documentId": "res_123",
  "activeState": {
    "fontId": "font_lora",
    "colorThemeId": "theme_forest",
    "schemaVersion": "1.0"
  },
  "warning": null
}
```

Response (premium option rejected):
```json
{
  "documentId": "res_123",
  "errorCode": "PREMIUM_CUSTOMIZATION_LOCKED",
  "message": "Lora font requires a Premium plan. Your current selection has been reverted.",
  "activeState": {
    "fontId": "font_roboto",
    "colorThemeId": "theme_navy",
    "schemaVersion": "1.0"
  }
}
```

### `PATCH /documents/{id}/layout-order`

Request:
```json

    "sec_experience": ["exp_003", "exp_001", "exp_002"]
```

## Premium-Feature Detection For Export

When export is triggered, the export service inspects `DocumentCustomizationState` for premium token references:

```text
For each active customization token (fontId, colorThemeId, backgroundStyleId, etc.):
  if token.isPremium == true AND user.plan != premium:
    return PREMIUM_FEATURES_USED → upgrade required to download
```

## Edge Cases

- Capability set changes after a template update (e.g., a font is deprecated) → stored state references stale IDs. Backend returns `activeState` with resolved/null values and a warning.
- Stored premium option becomes unavailable after downgrade → document remains viewable but customization is frozen; editing customization prompts re-select of free options.
- Layout order references a section later removed by product rules → reorder request is rejected with validation error; stored order is cleaned up on next save.
- Concurrent reorder from two tabs → version token prevents overwrite; second request gets HTTP 409.

## Testing Focus

- Capability retrieval by template and entitlement (does free user see premium options as locked vs. hidden?).
- Schema compatibility between preview and export consumers (do both read the same customization state?).
- Validation of premium options submitted by free users.
- Versioning: does upgrading schema version break existing stored states?

## Developer Notes

- Keep stored token IDs stable and renderer-friendly — avoid inline CSS or computed style strings.
- Version the customization schema from day one (`schemaVersion: "1.0"`). Schema migrations on stored `DocumentCustomizationState` should handle forward-compatibility (unknown keys are preserved) and backward-compatibility (missing keys get defaults).
- The `CustomizationCapabilitySet` is derived from Template metadata + Plan capabilities + ATS-safe constraints. Cache it; it changes only when template or plan definitions change.
