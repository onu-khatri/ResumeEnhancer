## [BILL-FE-001] — Export Experience And Upgrade Entitlement UX

**Module:** Export & Billing  
**Layer:** Frontend  
**Priority:** Must Have  
**Persona:** Free User, Premium Subscriber  
**Dependency:** BILL-BE-001  
**Source Classification:** Observed, Documented, Inferred, Recommended

### User Story

As a user preparing to apply,  
I want to export my resume in allowed formats and understand when an upgrade is required,  
so that I can complete my application work without pricing surprises or confusing failures.

### Description

This story covers the frontend experience for exporting a resume and, when necessary, transitioning into an upgrade path. The export UI must make available formats explicit, show locked features clearly, validate resume readiness before generation, and provide a transparent and non-destructive upgrade experience.

**Research context:** Both competitors monetize at export: Novorésumé uses a "preview premium features, pay to download" gate (white-star features can be tested but not downloaded free); Resume Now uses a "free plain-text, paid PDF/DOCX" ladder. Novorésumé explicitly retains user data after Premium expiry — content is kept, export capability is reduced to free-tier level. Both communicate what is free and what is paid before the user clicks export. Four export-blocking states must be visually distinct: content-not-ready, plan-doesn't-allow, export-in-progress, and export-failed-operationally.

### Scope

**Included In Scope**

- Export CTA and export modal or equivalent UI.
- Format availability and plan-lock indicators.
- Export progress and result state.
- Upgrade prompt and plan comparison state.
- Checkout handoff entry point.
- Validation blocker display for export-readiness issues.

**Out Of Scope**

- Full subscription management portal.
- Refund-management UI.
- Multi-document bulk export.
- Administrative pricing configuration UI.

### Preconditions

- User is authenticated — export is a gated action that requires a valid session so the system can enforce plan entitlements and associate the export job with the correct account.
- Resume exists — the export flow needs a saved resume to reference; if the draft was never persisted or has been deleted, the UI must route the user to create or restore content before offering export.
- Export formats and entitlements are available — the frontend must have the full format entitlement matrix (which formats are free vs. premium for the current plan) loaded before the export modal opens so it can mark locks accurately instead of guessing.
- Checkout handoff route exists — the upgrade path requires a working checkout entry point that can preserve the user's place in the export flow and return them to it after payment completes.

### Detailed Workflow

1. User clicks export from builder or dashboard context.
2. UI shows available formats and whether they are included in the current plan.
3. If the selected format is allowed, export request is submitted.
4. UI shows progress until artifact is ready.
5. If the selected format is locked, the UI shows plan comparison and upgrade CTA.
6. After successful checkout, the user returns to the export flow and can retry without losing draft context.

### Functional Requirements

- The export UI must show available, locked, and unavailable states separately.
- Resume validation issues that block export must be distinguishable from monetization restrictions.
- Locked states must explain value, not only deny access.
- The UI must prevent accidental duplicate export requests.
- Export completion must provide either direct download, secure link, or clear next action.

### Acceptance Criteria

**AC1 — Happy Path**  
Given a user has export rights for a selected format  
When they start export  
Then the UI shows progress and delivers the generated document or secure retrieval state.

**AC2 — Premium Restriction**  
Given a free user selects a locked format or premium feature  
When they try to export  
Then the UI explains the restriction, compares plans, and preserves the draft and current context.

**AC3 — Validation**  
Given the resume is missing required content or has unresolved blocking issues  
When export starts  
Then the UI blocks generation and points back to the relevant sections for correction.

**AC4 — Error Handling**  
Given generation fails  
When the failure occurs  
Then the UI explains the issue, avoids duplicate charges or duplicate requests, and offers retry.

**AC5 — Post-Upgrade Continuity**  
Given the user upgrades mid-flow  
When they return from checkout  
Then the export path resumes cleanly without requiring the user to rebuild or relocate their resume.

### Business Rules

- Free and premium export entitlements must be visible before final action — the export UI must clearly label which formats are included in the current plan and which are locked before the user commits to an export, so there are no pricing surprises at the moment of download.
- Locked features should show value framing and available alternatives — when a format or feature is premium-locked, the UI should explain what the user gains (e.g., "editable DOCX for tailoring") and point to the closest free alternative rather than just showing a denial.
- Export must not silently downgrade styling or output quality without warning — if the user's resume uses premium templates or styling but they export to a free format, the UI must warn them of any loss of formatting or fidelity before generating the file.
- Upgrade messaging must not imply permanent entitlement until checkout confirms success — the UI must use provisional language (e.g., "upgrade to download") and only confirm unlocked access after a successful payment, never assuming entitlement mid-checkout.
- If the product adopts a "preview premium features, pay to download" model, the export UI must distinguish between "this document uses premium features" (must pay to download) and "this format is premium-only" (must upgrade for the format) — these two monetization triggers have different explanations and different remediation paths and must not be conflated.
- Data retention after plan expiry: user content is preserved; export capability is reduced to free-tier rules — when a subscription lapses, the user's resume data remains intact, but the export UI must reflect the downgraded free-tier format set without ever implying their content was deleted.

### Validation Rules

- Resume must meet minimum content standards.
- Selected format must be allowed by plan.
- Prevent repeated clicks during in-flight export.
- Prevent export request from a stale or deleted draft.

### Error Handling

- Maintain clear status: queued, generating, ready, failed — the export UI must expose an explicit state machine so the user always knows where their job is in the pipeline, and each state must have a distinct visual treatment so progress is legible at a glance.
- Route billing failures separately from document-generation failures — a failed payment should surface a billing-specific message with a path back to checkout, while a generation failure should offer a technical retry, keeping these two very different problems clearly separated so the user isn't confused about whether they were charged.
- Preserve last successful export metadata when appropriate — if a retry or new export fails, the UI should retain a record of the last successful export (format, timestamp, and retrieval link) so the user still has a path to a usable document rather than starting from nothing.

### Security Considerations

- Export download links must be time-limited.
- Do not leak private resume data through cached or guessable URLs.
- Payment and entitlement UI must not expose sensitive billing details.

### Analytics / Tracking

- `resume_export_completed`
- `resume_export_failed`
- `upgrade_prompt_viewed`
- `checkout_started`
- `checkout_returned_to_export`

### API Dependencies

- `POST /resumes/{id}/export`
- `GET /exports/{id}`
- `GET /plans`
- `POST /billing/checkout`

### Data Requirements

- Entitlements
- Export job status
- Plan and pricing metadata
- Checkout return state

### UX Notes

- Put format availability near the export CTA.
- Use side-by-side comparison for upgrade messaging.
- Keep validation blockers actionable and linked to editing paths.

### UI/UX Design Requirements

- Export UX must feel final, trustworthy, and commercially transparent.
- The user should immediately understand:
  - what format they are getting
  - whether it is included in their current plan
  - whether the resume is ready to export
- Upgrade prompts must look intentional and premium, not like error screens.
- The visual tone should reinforce that export is the completion point of real work.

### React UI Implementation Notes

- Model export flow as a clear state machine in React:
  - choose format
  - validate
  - generating
  - ready
  - failed
  - locked / upgrade required
- Keep checkout-return handling isolated in a resumable flow hook or feature state module.
- Use reusable modal, banner, and comparison components so export, AI paywalls, and premium-template locks feel part of one system.

### Layout And Responsive Requirements

- Desktop:
  - export modal or panel can show format options and plan comparison side by side
- Tablet:
  - comparison may collapse below format list
- Mobile:
  - use stacked cards and clear CTA hierarchy
  - avoid dense pricing tables that require horizontal scrolling

### Visual And Interaction Requirements

- Locked and unlocked formats must be visually distinct at a glance.
- Export progress must feel active and reliable, especially if generation takes more than a few seconds.
- Validation blockers should appear as fixable checklist items rather than generic error text.
- Checkout handoff and return states should preserve visual continuity with the product rather than feel like an abrupt mode switch.

### Definition Of Ready For Engineering

- Format entitlement matrix is approved.
- Checkout return-flow behavior is approved.
- Export status model is defined.

### Definition of Done

- Export flow handles free, premium, validation, and error states cleanly.
- Upgrade prompts are informative and non-destructive.
- Core analytics and accessibility checks are complete.
