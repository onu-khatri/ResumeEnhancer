# Supporting Information — Template Inventory, Metadata, And Publication Management Services

## Proposed APIs

- `GET /admin/templates`
- `GET /admin/templates/{id}`
- `PATCH /admin/templates/{id}`

## Example Template Summary

```json
{
  "id": "tpl_123",
  "type": "resume",
  "status": "published",
  "isPremium": true,
  "category": "modern"
}
```

## Proposed Entities

- `Template`
- `TemplateVersion`
- `AuditLog`

## Suggested Technical Controls

- Template-type allowlist: restrict `kind` to `resume` and `cover_letter` so unknown template families are rejected outright.
- Commercial/publication transition validation: enforce an approved state machine for publication and premium changes, blocking unsupported transitions.
- Audit logging for sensitive changes: record before/after state for every premium toggle and publication transition with an attributable actor.

## Edge Cases

- Template version exists but current version metadata incomplete: the service must not crash on missing version detail and should flag the inconsistency clearly.
- Publication state updated while template preview asset is missing: reject or warn on publish until a preview asset is present, depending on policy.
- Premium flag toggled inconsistently with entitlement assumptions: validate premium changes against entitlement rules and surface conflicts before persisting.

## Test Focus

- State transition validation: verify only approved transitions are accepted and invalid ones are rejected safely.
- Authorization: confirm only authorized roles can mutate commercial or publication fields.
- Audit logging: ensure every sensitive change produces a complete before/after audit record.

## Developer Notes

- Keep admin metadata contracts distinct from public template-catalog contracts, so internal fields do not leak to the public API surface.
- Plan ahead for future template diagnostics without overloading MVP contracts now, adding extension points without committing to full diagnostic features.
