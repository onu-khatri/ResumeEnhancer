## Design Token Guidance

### Typography

- Workspace header should use strong but compact heading styles.
- Section titles should be visually distinct from field labels.
- Save-state and metadata text should use a quieter utility style.
- Preview typography should not inherit generic app typography blindly; it should align with template render rules.

### Color

- Builder chrome should use calm neutral surfaces to keep resume content primary.
- Active section state should use a focused accent treatment.
- Validation severity should use a consistent semantic scale across builder, analysis, and export.
- Preview paper surface should contrast clearly from surrounding app chrome.

### Spacing

- Workspace columns need enough gutter space to separate edit and preview regions.
- Repeatable items should have generous internal spacing to reduce cognitive load.
- Dense form stacking should be avoided, especially in experience and education sections.

### Elevation And Borders

- Use light panel boundaries and subtle elevation to define workspace regions.
- Avoid heavy dashboard-style cards that compete with the document preview.

## Section Field Guidance

| Section | Fields |
| --- | --- |
| Header | full name, phone, email, location, links, headline |
| Summary | summary text |
| Experience | title, company, location, start date, end date, current flag, bullet list |
| Education | school, degree, field, location, start date, end date |
| Skills | skill name, category, proficiency later |

- The header is the identity block and must support validation for email and phone formats, while links and location remain free-form. Experience and education both need date-range handling with a current-position flag that suppresses the end date.

## State Matrix

| State | Trigger | Expected UX |
| --- | --- | --- |
| Loading | draft fetch pending | skeleton layout |
| Ready | draft loaded | interactive editor |
| Saving | autosave active | non-blocking saving indicator |
| Saved | last mutation persisted | saved label or timestamp |
| Save Failed | API failure | visible retry, local edits retained |
| Conflict | version mismatch | block overwrite, prompt refresh/resolve |

- The loading state should use a skeleton that matches the final layout to avoid layout shift. Save Failed must keep the user's edits locally so a transient network issue never destroys their work, while Conflict requires an explicit decision before overwriting.

## Edge Cases

- Resume exceeds page length target
  - Content can overflow the target page count, so the preview must render pagination faithfully and surface an overflow indicator, letting the user trim rather than discovering the issue only at export.
- Overlapping employment dates
  - Date ranges may overlap or be inverted, so validation should flag implausible timelines without hard-blocking, since the user may intentionally represent overlapping roles.
- Special characters break layout
  - Unusual characters or long unbroken strings can overflow the template layout, so the preview must handle wrapping and truncation gracefully while keeping the underlying data intact.
- Concurrent edit from another tab
  - Two tabs can mutate the same draft, so the version-conflict state must prevent silent overwrite and offer refresh or resolve actions.
- Section deleted in another session while still open
  - A section removed elsewhere may still be open in this tab, so mutations on a missing section must surface a not-found/conflict state rather than resurrecting stale data.

## Test Focus

- Long text overflow
  - Verify long names, summaries, and unbroken URLs render without breaking the preview or hiding content.
- Keyboard reordering
  - Confirm reorder controls are fully keyboard-operable and persist order correctly across save.
- Offline edit recovery
  - Simulate a dropped connection and confirm local edits are retained and can be retried without loss.
- Section hide/show persistence
  - Assert visibility toggles persist through save and reflect correctly in preview and export.
- Save-state transition accuracy
  - Verify the indicator transitions correctly through saving, saved, failed, and conflict under normal and error conditions.

## Developer Notes

- Use local draft state that can survive transient save failures.
  - Keeping edits in local state until confirmed persisted means a temporary network failure never forces the user to retype content. The save pipeline queues and retries mutations while the UI stays interactive.
- Avoid tightly coupling section forms to a single template; rendering should handle layout differences.
  - The section editor should be template-agnostic so switching templates does not require different form logic, while the preview layer owns template-specific rendering.
- Consider a schema-driven section form approach if many additional sections are planned.
  - If the section catalog grows, a schema-driven form generator reduces per-section code duplication and keeps validation consistent across section types.

## Professional UI Notes

- The builder should feel closer to a focused design tool than a CRUD admin panel.
- Avoid over-decoration; document clarity and editing confidence should drive the visual system.
