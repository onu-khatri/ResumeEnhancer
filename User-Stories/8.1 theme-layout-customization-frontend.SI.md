# Supporting Information — Theme, Appearance, And Custom Layout Editing Experience

## Suggested Screens

- Builder customization panel
- Theme browser
- Layout-order editor
- Premium-lock explanation state for advanced options

## Component Inventory

| Component | Purpose | Notes |
| --- | --- | --- |
| `CustomizationPanel` | groups theme/layout controls | feature-specific |
| `ThemeSwatchGrid` | visual theme selection | reusable |
| `FontSelector` | typography option control | reusable |
| `StyleOptionGroup` | picture/rating/icon style controls | reusable |
| `LayoutOrderEditor` | section/item ordering controls | feature-specific |
| `CustomizationLockCard` | premium or unsupported explanation | reusable |
| `CustomizationResetAction` | restore defaults quickly | reusable |

## Design Token Guidance

- The customization area should feel premium and visually richer than plain settings UI.
- Swatches, typography previews, and visual style controls should communicate outcomes before selection.
- Keep enough white space so the panel does not become visually noisy.

## Edge Cases

- User selects a theme option unsupported by the active template.
  - Not every template exposes every customization control, so the panel must disable or explain unsupported options rather than allowing a selection that the preview silently ignores. The lock or unsupported state should name the limitation clearly.
- Layout reorder changes pagination dramatically.
  - Moving sections can push content across page boundaries, so the preview must re-render pagination immediately and flag overflow so the user understands the layout consequence before saving.
- Premium theme applied during trial/preview then export is locked.
  - A premium theme can be previewed before purchase, but export must be gated until entitlement is confirmed, and the transition from preview to locked export must be explained honestly without implying the style was saved for free.

## Testing Focus

- Preview responsiveness.
  - Confirm customization changes reflect in the live preview promptly and that the preview remains correct across theme and layout switches.
- Rollback after failed layout-save mutation.
  - Simulate a save failure and verify the UI reverts to the last persisted customization state without leaving the user in a half-applied visual state.
- Premium lock and ATS-safe option messaging.
  - Assert that premium controls show the correct lock explanation and that ATS-safety implications are surfaced where relevant.

## Developer Notes

- Keep customization controls data-driven from template capabilities.
  - Controls should render from the template's declared capability set so adding a template or option does not require rewriting the panel. A capability mismatch should degrade to a disabled or hidden control rather than a broken one.
- Avoid embedding hardcoded theme inventories into presentation components.
  - Theme definitions should come from shared configuration or data so the swatch grid and preview stay in sync with the backend's supported theme list.
