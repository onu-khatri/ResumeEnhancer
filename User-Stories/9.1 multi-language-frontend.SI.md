# Supporting Information — Multi-Language Resume And Cover Letter Authoring Experience

## Suggested Screens

- New document language chooser
- Duplicate-as-new-language flow
- Workspace cards with language metadata
- Builder header with language badge and variant actions

## Design Token Guidance

- Language badges should use subtle, consistent identity styling rather than loud flag-heavy visuals.
- Keep variant-management UI visually related to document identity components.
- Localized labels should not break spacing or hierarchy in the builder shell.

## Example State Shape

```ts
type DocumentLanguageMeta = {
  code: string;
  label: string;
  isDefault: boolean;
};

type DocumentVariantSummary = {
  id: string;
  type: "resume" | "cover_letter";
  language: DocumentLanguageMeta;
  relatedVariantIds: string[];
};
```

## Edge Cases

- User creates two resumes in same role but different languages and similar names.
  - Near-identical titles across languages make workspace identification hard, so the language badge and a distinguishing subtitle must be prominent to prevent accidental edits to the wrong variant.
- Locale pack is incomplete for one section label.
  - A missing localized label must fall back to the default language without breaking layout, and the UI should degrade gracefully rather than rendering raw keys.
- User duplicates a resume into a language with unsupported rating/section-label conventions.
  - Some languages or locales may not support certain conventions, so the variant flow must surface limitations and adjust defaults rather than silently copying incompatible content.
- User expects automatic translation because of the language-selector placement.
  - Choosing a language for a new variant does not imply translation, so the UI must clearly state that content is not auto-translated and the user must supply the localized text themselves.

## Testing Focus

- Language metadata visibility in workspace and builder.
  - Verify the language badge appears consistently on workspace cards and the builder header, and that it updates correctly after variant creation.
- Unsaved-change protection during variant creation or switching.
  - Confirm switching or duplicating variants does not silently discard unsaved edits, and that a prompt or save path is provided.
- Fallback behavior when locale resources partially fail.
  - Simulate a missing or failed locale pack and assert the UI falls back to defaults without crashing or mislabeling sections.

## Developer Notes

- Keep language metadata close to document summaries so workspace and builder share the same truth.
  - Embedding language in the document summary payload ensures every surface reads the same source rather than reconstructing it inconsistently.
- Avoid tying document language too tightly to account-level locale preference.
  - Document language and interface locale are independent concerns; a user's UI language may differ from the resume's content language, so keep them separate.
- Prefer explicit localized strings for section labels over runtime-generated translations.
  - Curated locale packs produce higher-quality, predictable section labels than on-the-fly machine translation, avoiding awkward or incorrect headings.
