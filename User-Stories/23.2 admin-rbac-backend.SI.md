# Supporting Information — Role, Access Profile, And Admin User Management Services

## Proposed APIs

- `GET /admin/users`
- `GET /admin/roles`
- `GET /admin/access-profiles`
- `PATCH /admin/users/{id}/roles`

## Example Assignment Update Payload

```json
{
  "roles": ["support_agent"],
  "accessProfiles": ["support_limited"]
}
```

## Proposed Entities

- `User`
- `Role`
- `AccessProfile`
- `UserRole`
- `AuditLog`

## Suggested Technical Controls

- Admin policy enforcement layer: centralize authorization checks so every mutation is validated against a single, consistent policy.
- Sensitive-mutation audit logging: record acting admin, target user, and before/after assignment state for every access change.
- Visibility-scope constraints: ensure retrieval returns only users and roles within the requesting operator's scope.

## Edge Cases

- Attempt to remove last super admin: the service must block this protected-role change and return a clear policy error.
- Assignment update based on stale role definitions: reject or re-validate when a referenced role has changed since the client loaded it.
- Audit write fails after access mutation is prepared: the service must avoid committing the access change without a corresponding audit record.

## Test Focus

- Permission enforcement: verify operators cannot act outside their role's allowed scope.
- Policy validation: ensure protected roles and invalid assignments are rejected.
- Audit integrity: confirm every sensitive change produces a complete, attributable audit entry.
- Safe failure for sensitive changes: verify a failure in audit or persistence does not leave a half-applied assignment.

## Developer Notes

- Keep internal-role definitions configurable enough for growth, but do not over-design for every future enterprise need in MVP.
- Make audit logs easy to inspect later in support/admin tools, choosing fields and formats that downstream visibility can consume.
