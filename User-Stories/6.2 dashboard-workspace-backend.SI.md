# Supporting Information — Saved Documents Index And Workspace Management APIs

## Proposed APIs

- `GET /documents`
- `PATCH /documents/{id}`
- `POST /documents/{id}/duplicate`
- `DELETE /documents/{id}` or `POST /documents/{id}/archive`

## Example Summary Payload

```json
{
  "documents": [
    {
      "id": "res_123",
      "type": "resume",
      "title": "Product Manager Resume",
      "lastUpdatedAt": "2026-08-14T10:15:00Z",
      "templateId": "tpl_modern_01"
    }
  ]
}
```

## Proposed Entities

- `DocumentSummary`
- `Resume`
- `CoverLetter`
- `AuditLog`

## Suggested Technical Controls

- Ownership-based query filters. Every list and management query must include the owner condition at the database level so cross-user access is impossible by construction.
- Lightweight summary projections. Return only summary fields (id, type, title, timestamps, template reference) so large libraries list quickly without pulling editor payloads.
- Duplicate lineage metadata. Persist a source reference on duplicates so tailoring and support traceability are preserved even if the UI does not display it.

## Edge Cases

- Duplicate title collisions. Duplication must produce a deterministic, non-colliding default title rather than failing on a unique-name constraint.
- Archived document appears in stale client state. Clients holding old list state must reconcile gracefully when an item is archived or deleted elsewhere.
- User has a very large document library. Listing must remain fast through summary projections and pagination, avoiding full-content loads.

## Test Focus

- Summary-list authorization. Confirm the endpoint returns only the requesting user's documents and denies foreign IDs.
- Duplicate consistency. Verify the copy is complete, independently editable, and carries correct lineage.
- Rename validation. Confirm length and character rules reject invalid titles with field-scoped errors.
- Filter and search scoping. Ensure filters and search never widen results beyond owned documents.

## Developer Notes

- Keep workspace list endpoints distinct from editor-detail endpoints. Separate contracts keep the lightweight list independent from heavy content retrieval.
- Support future document tags or categories in the summary model even if MVP UI uses only basic type filters. Designing the summary with extensibility avoids a schema change later.
