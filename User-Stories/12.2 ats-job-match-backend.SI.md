# Supporting Information — Resume Analysis And Job Match Scoring Engine

## Proposed APIs

- `POST /analysis/resume`
- `POST /analysis/job-match`
- `GET /analysis/{id}`

## Proposed Entities

- `ResumeAnalysis`
  - Base report aggregate holding the resume reference, version snapshot, mode, overall score, and the category results. It is the parent record the other analysis types link to.
- `ATSAnalysis`
  - Formatting and parseability-specific findings such as font, spacing, and machine-readability issues that are not about keyword content.
- `JobDescription`
  - The optional target job posting captured for matching, stored as a snapshot so the score remains reproducible against the exact text used.
- `JobMatch`
  - Keyword-alignment and role-relevance results computed by comparing the resume against a `JobDescription`, including matched and missing keywords.

## Example Entity Shape

```json
{
  "analysisId": "ana_123",
  "resumeId": "res_123",
  "resumeVersion": 12,
  "mode": "job_match",
  "overallScore": 78,
  "createdAt": "2026-08-14T10:00:00Z",
  "jobDescriptionSnapshotHash": "sha256:abc123"
}
```

## Suggested Score Categories

- content completeness
  - Measures whether essential sections are present and populated, independent of formatting.
- ATS formatting
  - Evaluates machine-readability risks such as tables, images, and non-standard fonts.
- keyword alignment
  - Compares resume terms against the job description to find coverage and gaps.
- impact language
  - Scores the presence of action-oriented, quantified language rather than passive duties.
- section organization
  - Assesses logical ordering and section clarity.
- role relevance
  - Weighs how closely experience maps to the target role's requirements.

## Example Analysis Result Shape

```json
{
  "analysisId": "ana_123",
  "resumeId": "res_123",
  "resumeVersion": 12,
  "mode": "job_match",
  "overallScore": 78,

      "code": "keyword_alignment",

    }

    {
      "severity": "high",
      "categoryCode": "keyword_alignment",
      "message": "Add product strategy keywords from the job description."
    }
  ]
}
```

## Suggested Technical Controls

- Rule configuration store
  - Scoring rules live in configuration rather than hardcoded logic, so thresholds and weights can be tuned without deploying code.
- Resume version snapshotting
  - The analysis records the exact resume version it evaluated so the report stays traceable even as the draft changes.
- Background queue for heavy runs
  - Long-running scoring jobs are queued asynchronously so the request does not block and results can be polled.

## Edge Cases

- Empty imported sections
  - An analysis over empty content must not fabricate a score; it should return low-completeness results with clear "add content" guidance.
- Repeated reruns against same job description
  - Identical inputs should produce deterministic, stable results, and repeated runs should be efficient and consistent rather than drifting.
- Resume text in unsupported language
  - Unsupported content languages must be detected and reported, with scoring either limited or flagged as low-confidence.
- Analysis partially succeeds but one rule group errors
  - A partial failure should still return usable results with an explicit partial-status flag rather than failing the whole run.

## Test Focus

- Scoring determinism
  - Verify identical inputs yield identical scores and recommendations across runs.
- Partial failure behavior
  - Assert that a failed rule group degrades to partial results with a clear status instead of a total failure.
- Version traceability
  - Confirm each report records the resume version and job-description snapshot used.
- Payload size and performance under large job descriptions
  - Validate that large inputs are bounded and scoring remains within acceptable latency and payload limits.

## Developer Notes

- Persist the exact job-description snapshot used for scoring or a normalized hash plus stored content policy.
  - Storing either the snapshot or its hash keeps results auditable and reproducible without necessarily retaining full text indefinitely.
- Keep recommendation generation deterministic where possible for easier QA.
  - Deterministic rules make test assertions stable and reduce flaky, hard-to-reproduce recommendations.
