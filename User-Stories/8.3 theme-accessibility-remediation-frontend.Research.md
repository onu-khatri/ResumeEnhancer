# Research - Theme Accessibility Remediation Across The Frontend

## Research Basis

This is an evidence-led corrective frontend story. It is based on the repository's existing WCAG 2.2 AA baseline, the implemented theme provider, the current CSS token definitions, the source-color inventory, and W3C's informative explanations of the WCAG contrast criteria.

## Accessibility Standard

| Requirement | WCAG 2.2 AA interpretation for this story |
| --- | --- |
| Text contrast | Normal text and images of text require at least 4.5:1; qualifying large text requires at least 3:1. Placeholder and hover/focus text are included when rendered. |
| Non-text contrast | Visual information needed to identify an operable control, its state, or a meaningful graphic requires at least 3:1 against adjacent colors. |
| Focus | An author-supplied focus indicator must remain visible and sufficiently contrasting against its adjacent background. |
| Inactive controls | A genuinely inactive control is exempt from the contrast requirement, but must not be used as an exception for an operable component. |

## Requirement Interpretation

- Theme accessibility is a platform-wide quality requirement, not a visual-polish task limited to the theme selector or resume customization panel.
- The current use of direct palette utilities and Midnight-only `dark:` variants is incompatible with a three-theme system because Forest cannot express distinct semantic intent through a binary light/dark branch.
- The safest remediation order is semantic token definition, shared primitive migration, feature-surface migration, then automated and visual regression coverage.
- A passing default theme is insufficient. Every approval and verification result must name Light, Midnight, and Forest.

## Risks If Under-Specified

- Fixes may address only reported Light-theme screens and reintroduce failures in Midnight or Forest.
- A new hard-coded palette utility can bypass the token system and create a regression without test coverage.
- Component tests can pass behaviorally while visible labels, placeholders, focus indicators, and selected states remain inaccessible.
- Treating disabled styling as a blanket exception can mask operable-control contrast failures.
