# Research — Template Inventory, Metadata, And Publication Management Services

## Research Basis

Template catalogs are foundational public and product assets in both selected competitors. That implies a template-specific internal service for metadata, commercial state, and availability rather than only static frontend content.

## Requirement Interpretation

- Template metadata and state are product-critical, so the backend must treat them as a dedicated domain rather than folding them into generic content inventory.
- Internal services should expose template-type, premium/public, and publication metadata explicitly, since these fields drive both entitlement and discovery behavior.
- Resume and cover-letter templates should share family-level handling where useful, avoiding duplicate logic while preserving type-specific rules.

## Risks If Under-Specified

- Template operations become brittle or too engineering-dependent, pushing routine portfolio changes back onto developers.
- Commercial and public-state mismatches become more likely, as premium toggles and publication states fall out of sync with product reality.
- Internal template quality control becomes harder, since operators lack reliable visibility into the current portfolio state.

## Recommended Backend Interpretation

- Create a template-specific admin service layer with safe state transitions and auditability, giving operators a governed way to manage the catalog.
- Keep authoring complexity out of scope initially, focusing first on the state and metadata that affect public product behavior.
