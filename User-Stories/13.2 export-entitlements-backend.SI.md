# Supporting Information — Export Processing, Billing Checkout, And Entitlement Evaluation

## Proposed APIs

- `GET /plans`
- `POST /billing/checkout`
- `POST /billing/webhooks/provider`
- `POST /resumes/{id}/export`
- `GET /exports/{id}`

## Proposed Entities

- `Plan`
  - Catalog definition of an available commercial plan with code, cadence, and feature inclusions, used to render pricing and evaluate entitlements.
- `Subscription`
  - The user's active or historical plan membership linking the user to a `Plan` with a status and billing window.
- `Entitlement`
  - The resolved set of capabilities a user is allowed to use, derived from their subscription and used to gate export formats.
- `Payment`
  - A billing-provider transaction record used to reconcile checkout and webhook events.
- `Invoice`
  - A completed billing document for accounting and user-facing history.
- `Export`
  - An artifact-generation job that tracks requested format, source resume version, and delivery status.

## Suggested Export Status Model

- `queued`
  - The export request was accepted and is waiting for a worker.
- `generating`
  - The render worker is actively producing the artifact.
- `ready`
  - The artifact is available for retrieval via a signed URL.
- `failed`
  - Generation encountered an unrecoverable error and requires retry or support.
- `expired`
  - The signed download link or artifact retention window has lapsed.

## Suggested Checkout Status Model

- `created`
  - The checkout session was created but not yet completed.
- `pending_payment`
  - The user is in the provider's hosted flow.
- `paid`
  - Payment was captured but entitlements are not yet activated.
- `activation_pending`
  - Payment succeeded and entitlement activation is in progress.
- `activated`
  - Entitlements are live for the user.
- `failed`
  - The checkout or activation did not complete successfully.

## Edge Cases

- Duplicate provider webhook
  - The same webhook may be delivered more than once, so processing must be idempotent and not double-credit entitlements or create duplicate invoices.
- Payment success but export render failure
  - Payment and generation are independent, so a render failure after successful payment must allow a free retry without charging again or blocking the paid user.
- User downgrades while old export links remain active
  - Previously issued signed URLs must respect their expiration and should not grant indefinite access after downgrade.
- Checkout succeeds but entitlement cache is stale
  - The entitlement cache must be invalidated or refreshed on activation so the user is not blocked despite successful payment.

## Test Focus

- Webhook idempotency
  - Verify duplicate webhook deliveries produce a single, correct state change.
- Entitlement cache consistency
  - Assert that activation invalidates cached entitlements and that gated endpoints see the updated state promptly.
- Signed URL expiration behavior
  - Confirm expired URLs are rejected and that expiration is enforced on artifact retrieval.
- Export retry after successful upgrade
  - Verify a previously locked export can be re-attempted once entitlement is activated.

## Developer Notes

- Use signed URLs with short TTLs for artifact retrieval.
  - Short-lived signed URLs limit exposure and prevent permanent, shareable download links from leaking content.
- Record source resume version on each export artifact so support can understand what was generated.
  - Capturing the resume version alongside the artifact makes it possible to reconstruct exactly what the user exported when diagnosing issues.
