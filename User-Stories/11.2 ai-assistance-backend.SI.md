# Supporting Information — AI Request Orchestration, Safety, And Usage Accounting

## Proposed APIs

- `POST /ai/generate`
- `POST /ai/rewrite`
- `GET /ai/usage`

### API Detail: `POST /ai/generate`

Creates a new AI suggestion request. Supports multiple action types via the `actionType` field.

**Request:**
```json
{
  "actionType": "generate_summary",
  "resumeId": "res_123",
  "sectionId": "sec_summary",
  "resumeVersion": 12,
  "inputContext": {
    "existingText": "I am a software engineer...",
    "targetRole": "Senior Software Engineer",
    "targetIndustry": "fintech",
    "jobDescription": "Optional: pasted job description text for tailoring"
  },
  "idempotencyKey": "ik_abc_001"
}
```

**Response (success):**
```json
{
  "requestId": "air_456",
  "actionType": "generate_summary",
  "status": "completed",
  "suggestions": [
    {
      "id": "sug_001",
      "text": "Results-driven Senior Software Engineer with 6+ years building scalable fintech platforms...",
      "reasoningSummary": "Added metrics, stronger action verbs, and industry-specific context.",
      "confidence": "high"
    },
    {
      "id": "sug_002",
      "text": "Senior Software Engineer specializing in fintech...",
      "reasoningSummary": "Shorter alternative with focus on technical impact.",
      "confidence": "medium"
    }
  ],
  "usage": {
    "remaining": 8,
    "limit": 10,
    "periodEndsAt": "2026-08-31T23:59:59Z"
  }
}
```

**Response (quota exhausted):**
```json
{
  "requestId": "air_457",
  "status": "quota_exceeded",
  "usage": {
    "remaining": 0,
    "limit": 3,
    "periodEndsAt": "2026-08-31T23:59:59Z"
  },
  "message": "You've used all 3 AI actions this month. Upgrade to Premium for 50 actions/month."
}
```

**Response (moderation blocked):**
```json
{
  "requestId": "air_458",
  "status": "moderation_blocked",
  "message": "Your content could not be processed. Please review your input and try again.",
  "reasonCode": "policy_violation"
}
```

**Response (provider failure):**
```json
{
  "requestId": "air_459",
  "status": "failed",
  "errorCode": "provider_timeout",
  "message": "AI service is temporarily unavailable. Your quota has not been consumed. Please try again.",
  "retryAfterSeconds": 30
}
```

## Supported Action Types

| Action | Context Required | Typical Output | Premium |
| --- | --- | --- | --- |
| `generate_summary` | Role, experience level, target industry | 2–4 sentence professional summary | No (free) |
| `generate_bullets` | Role, existing text or job description | 3–5 resume-ready bullets with metrics | Yes |
| `rewrite_section` | Existing text, optional job description | Rewritten version with improved tone/clarity/impact | Yes |
| `generate_skills` | Experience context, target industry | 5–10 relevant skills with proficiency hints | Yes |
| `generate_objective` | Background, target role | 2–3 sentence career objective | Yes |
| `tailor_to_job` | Full resume context + job description | Section-by-section rewrite suggestions | Yes |

## Suggested Technical Controls

- Provider abstraction layer (supports swapping between OpenAI, Anthropic, etc.)
- Idempotency keys (duplicate key returns cached result without re-processing or re-decrementing quota)
- Moderation pass **after** provider response (before returning to client) — content that violates policy is not shown to the user but is logged for review
- Usage decrement occurs **only after successful provider response + passed moderation** — if either fails, quota is untouched
- Prompt templates stored server-side in configuration, not in client code
- No-fabrication prompt engineering: system instructions emphasize rephrasing/restructuring user-provided facts only; never inventing qualifications, job titles, metrics, or credentials

## Edge Cases

- Provider returns malformed JSON → transform to generic error, do not expose raw output
- User retries after timeout → idempotency key prevents double-charge
- Usage double-count race → idempotency key checked before quota decrement
- Moderation blocks content after provider succeeds → mark as `moderation_blocked`, do not decrement quota, log for review
- Provider rate-limited → return `provider_rate_limited` with `retryAfterSeconds`
- Input context too large → reject at validation step before calling provider

## Test Focus

- Quota decrement correctness (success, double-submit, failure paths)
- Moderation branch coverage (pass, block, flag)
- Provider failover behavior (timeout, rate-limit, malformed response)
- Idempotent retry handling
- No-fabrication prompt output quality (spot-check: does output invent titles, metrics, or credentials not in input?)

## Developer Notes

- Keep normalized AI response objects stable across providers — the client should not care whether OpenAI or Anthropic generated the text.
- Separate "provider succeeded" from "result can be shown to user" in the control flow — moderation is a distinct gating step.
- Store `AIRequest.inputContext` and `AIRequest.suggestions` as structured JSON, not opaque text, so future analytics can measure quality by action type and section.
