# Supporting Information — Admin Analytics And Audit Visibility Workspace

## Suggested Screens

- Internal analytics summary screen
- Audit log browser
- Permission-denied state

## Suggested Components

- Summary metric cards
- Audit table/list
- Filter/search bar
- Empty audit state

## Frontend Component Inventory

| Component | Responsibility | Reusability |
| --- | --- | --- |
| `OpsAnalyticsSummary` | internal summary cards | shared internal |
| `AuditLogTable` | searchable/filterable event list | shared internal |
| `AuditFilterBar` | time/category/actor filters | shared internal |
| `InternalPermissionState` | denied-access presentation | shared |

## Design Token Guidance

### Typography

- Internal metrics and audit labels should be compact and clear, prioritizing scannability for operators diagnosing issues.
- Actor, target, and timestamp fields should be legible at a glance so operators can answer who, what, and when quickly.

### Color

- Use restrained neutral and semantic colors, reserving saturated hues for genuinely important signals.
- Avoid flashy visualizations that reduce operational readability, keeping the workspace calm and information-first.

### Spacing

- Summary and audit surfaces should be clearly separated, so metrics and event lists do not blur together visually.
- Dense data should still remain readable, with enough row separation to scan audit entries without strain.

## API And Entity Map

- APIs: `GET /admin/analytics/summary`, `GET /admin/audit-logs`
- Entities: `AuditLog`, `AnalyticsSummary`

## Edge Cases

- Large audit result sets: the workspace must paginate and filter efficiently rather than loading an unbounded event list.
- Partial data unavailable: a failing analytics source should not blank the audit view, and vice versa.
- Operator lacks access to certain categories: restricted categories must be excluded cleanly rather than rendered as errors.

## Test Focus

- Partial failure rendering: verify one failed data block does not take down the whole workspace.
- Filter usability: confirm time, category, and actor filters return the expected audit subsets.
- Permission-denied handling: ensure blocked access shows a clear denial state distinct from empty data.

## Developer Notes

- Keep audit/event rendering optimized for operator scanning, not marketing-style dashboards, prioritizing clarity over decoration.
- Favor stable table/list patterns over unnecessary chart complexity in MVP, keeping the interface predictable and fast.
