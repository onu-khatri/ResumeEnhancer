# Research - Public Resume Enhancer Homepage And Builder Entry

## Research Basis

The revised homepage layout is based on the user-provided approved product direction dated August 24, 2026, combined with repository evidence. No new external research was required. The supplied layout describes the desired public information architecture and visual direction; it does not by itself validate customer testimonials, company logos, ratings, security claims, or live public-upload behavior.

## Conclusions

- **Observed:** The current frontend has no public homepage or live public upload flow. Resume import begins only after authentication, and analysis begins only after a saved resume exists.
- **Inferred:** An upload-led homepage can improve clarity of the intended product outcome without owning the underlying file or analysis workflow, if its handoff is explicit and secure.
- **Recommended:** Build the specified visual hierarchy using representative product data and reuse a consistent, allowlisted start handoff for hero and repeated CTAs.
- **Recommended:** Keep `HOME-FE-001` in `Draft` until proof content, route map, file-format policy, pre-authentication file-continuation policy, pricing claims, and telemetry consent are approved.

## Requirement Traceability

`HOME-FE-001` traces to `Business-Requirements/resume-platform-foundation.BR.md` section 13.1 for public acquisition and to `Business-Requirements/builder-domain.BR.md` for resume import as an entry path. No BR change is proposed: the homepage is an acquisition frontend slice; import, AI assistance, ATS analysis, and billing remain in their existing stories.

## Risks If Under-Specified

- A functional-looking public drop zone could create an unsafe anonymous file-upload path or falsely suggest immediate analysis.
- Sample score changes, keyword counts, and rewritten bullets could be interpreted as promises or real user results without clear representative labeling.
- Logos, testimonials, star ratings, "hired at" language, or privacy claims can create legal and trust risks without approved sources and rights.
- Navbar, footer, pricing, and CTA links may produce dead ends if downstream public routes are not implemented.
- A static hero statement that PDF/DOCX is supported could diverge from import policy or parsing capability.

## Open Questions

- Which proof items, company logos, testimonials, ratings, and customer-result claims have source approval for production use?
- Which file types and limits are canonical, and can a pre-authentication selected file be safely retained through onboarding?
- Which public destination routes are available at launch, including Resume Builder, Resume Checker, Templates, Resources, and Pricing?
- What Free/Pro inclusion language, payment policy, and final CTA copy are approved?
- What analytics provider, consent model, campaign fields, and conversion measure will be used?
- Does launch require SEO-specific metadata or a rendering change beyond the current React/Vite client?
