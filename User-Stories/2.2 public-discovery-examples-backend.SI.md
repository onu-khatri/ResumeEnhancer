# Supporting Information — Public Discovery Catalog And Funnel-Metadata Services

## Suggested Public Projections

| Projection | Purpose |
| --- | --- |
| `PublicTemplateSummary` | gallery/list rendering |
| `PublicExampleSummary` | example library rendering |
| `PublicCategorySummary` | category landing/filter metadata |
| `PublicAssetCta` | continuation target metadata |

## Example Response Shape

```json
{
  "items": [
    {
      "slug": "modern-ats-template",
      "title": "Modern ATS Resume Template",
      "assetType": "template",
      "categories": ["ats-friendly", "modern"],
      "thumbnailUrl": "/public-assets/templates/modern-ats.jpg",
      "cta": {
        "type": "use_template",
        "target": "/signup?source=template&asset=modern-ats-template"
      }
    }
  ]
}
```

## Edge Cases

- Asset published but thumbnail not yet available. The projection must tolerate a missing thumbnail and return the asset without a broken image reference.
- Category exists historically but currently has zero live assets. The category should remain resolvable with an empty asset set rather than disappearing or erroring, so old links stay valid.
- Public slug changes while old campaign URLs still exist. Slug changes must be handled with redirects or aliases so existing campaign and SEO links continue to resolve.

## Testing Focus

- Published-only filtering. Confirm draft and withdrawn assets are structurally absent from public projections, not just filtered by the frontend.
- CTA metadata correctness. Every returned CTA target must resolve to a valid onboarding or start entry point.
- Empty/unknown category behavior. Validate stable empty results and safe not-found responses for unknown slugs.

## Developer Notes

- Keep public slugs stable and version carefully. Slugs are a public contract, so renames need alias or redirect handling rather than silent changes.
- Public projections should be safe to cache at CDN or edge layers later. Design responses without per-user or sensitive data so caching never risks leaking information.
