# Supporting Information — Template Administration And Publication Management Interface

## Suggested Screens

- Template inventory view
- Template detail/metadata panel
- Publication/premium state update confirmation

## Suggested Components

- Template inventory table
- Thumbnail/preview cell
- Type/category filters
- Status badge
- Metadata edit form
- Sensitive change confirmation dialog

## Design Token Guidance

### Typography

- Template names and states should be highly scannable, so operators can identify a template and its status at a glance across a large inventory.
- Metadata labels must remain explicit and operational, avoiding marketing language in favor of precise field names.

### Color

- Publication and premium states should be clearly differentiated with restrained semantic styling, using distinct but calm hues for free versus premium and draft versus published.
- Color must be reinforced by labels or icons so commercial state is never communicated by color alone.

### Spacing

- Keep table/list readable while allowing template recognition via thumbnails, balancing row density with enough room for a recognizable preview.
- Separate high-impact commercial controls from routine edits so a premium or publication change is not triggered casually.

## API And Entity Map

- APIs: `GET /admin/templates`, `GET /admin/templates/{id}`, `PATCH /admin/templates/{id}`
- Entities: `Template`, `TemplateVersion`

## Edge Cases

- Template exists in backend but lacks public-preview asset: the UI should surface the missing preview without blocking metadata edits, and warn before publish.
- Premium state and publication state are inconsistent: the UI must make the mismatch visible so operators can correct it rather than silently rendering a contradictory state.
- Large mixed template families: the inventory must stay responsive and filterable when resume and cover-letter templates both number in the hundreds or thousands.

## Test Focus

- Inventory clarity: verify type, premium, and publication states are visually distinguishable and scannable.
- Metadata update safety: confirm edits are validated and only reflected after backend confirmation.
- Publication/premium state visibility: ensure commercial and publication signals are never ambiguous or conflated.

## Developer Notes

- Keep template-type and commercial metadata explicit in the contract, so the UI does not need to infer premium or type from names.
- Support future linkage to template preview validation or render diagnostics, leaving room for later quality checks without restructuring the page.
