# Supporting Information — Export Experience And Upgrade Entitlement UX

## Suggested Screens

- Export modal
- Upgrade comparison modal
- Checkout handoff state
- Export history list
- Export-failed recovery state

## Suggested Components

- Format picker
- Entitlement badge
- Export progress banner
- Plan comparison table
- Retry action
- Validation blocker list

## Design Token Guidance

### Typography

- Export modal title should signal finalization and clarity.
- Format labels should be short and highly scannable.
- Upgrade comparison text should be concise and benefit-oriented.

### Color

- Available vs locked format states must be distinguishable immediately.
- Export progress states should use a confidence-building visual treatment.
- Upgrade surfaces can use a premium accent system, but must remain consistent with the product palette.

### Spacing

- Format choices need enough spacing to prevent misclicks.
- Validation blocker list should be visually separated from monetization messaging.
- Download-ready state should feel clean and uncluttered.

## API And Entity Map

- APIs: `POST /resumes/{id}/export`, `GET /exports/{id}`, `GET /plans`, `POST /billing/checkout`
  - The export endpoint initiates generation, the status endpoint polls for readiness, and the plans/checkout endpoints drive the upgrade path when a requested format is locked. The frontend sequences these so a locked export can flow into checkout and back.
- Entities: `Export`, `Subscription`, `Plan`, `Entitlement`, `Invoice`
  - `Export` tracks the artifact generation lifecycle, while `Plan`, `Subscription`, and `Entitlement` model what a user is allowed to do and `Invoice` captures completed billing records.

## Edge Cases

- Export finishes after user closes modal
  - The user may navigate away while generation is in progress, so the artifact must remain retrievable via the export history or a return state rather than being lost.
- Plan changes while editor is open
  - If entitlements change mid-session, the UI must refresh the available formats and not present stale locked/unlocked states.
- Payment succeeds but entitlement cache is stale
  - The UI may still show a lock briefly after payment, so it must re-verify entitlement before blocking an export.
- Export requested on a stale resume version
  - Exporting a superseded version must either export the current saved version or warn clearly, rather than silently producing a mismatched document.

## Test Focus

- Locked-format messaging
  - Verify locked formats are clearly marked and that choosing one leads to the correct upgrade explanation without implying a technical error.
- Retry without duplicate export requests
  - Confirm a failed export can be retried without creating duplicate artifacts or charging multiple times.
- Mobile rendering of pricing comparison
  - Assert the plan comparison and checkout handoff remain usable on small screens.
- Return from checkout directly into export continuation
  - Verify that completing checkout restores the export flow and re-enables the requested format.

## Developer Notes

- Keep checkout-return state lightweight and durable across refresh.
  - The return state must survive a refresh so a user who refreshes after checkout still lands on the correct export continuation.
- Avoid assuming export completion must happen in the same browser tab session.
  - Generation is asynchronous, so the UI must poll or subscribe for status rather than waiting synchronously on a single tab.

## Professional UI Notes

- The export flow should feel like the polished completion of the user’s work.
- Avoid making premium messaging feel like an interruption disguised as an error.
