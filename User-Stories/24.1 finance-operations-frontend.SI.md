## Design Token Guidance

### Typography

- Financial states and identifiers must be easy to scan and compare, using tabular figures and clear label separation for amounts and dates.
- Status and identifier text should remain legible at a glance so operators can quickly verify billing truth.

### Color

- Use semantic status colors conservatively and consistently, applying the same hue to the same state across subscription, payment, and refund views.
- Avoid color-only status communication, pairing color with text or icons for accessibility and low ambiguity.

### Spacing

- Dense operational data should still preserve legibility and row separation, keeping rows readable without excessive vertical waste.
- Separate subscription, payment, and refund signals so distinct commercial states are never visually conflated.

## API And Entity Map

- APIs: `GET /admin/billing/summary`, `GET /admin/billing/transactions`, `GET /admin/billing/refunds`
- Entities: `Subscription`, `Payment`, `Refund`, `Invoice`

## Edge Cases

- Payment succeeded but entitlement failed: the UI must expose both facts so an operator can see the mismatch and initiate a fix.
- Refund pending while subscription status still active: present the two states distinctly rather than conflating them into a single misleading status.
- Large transaction volume: pagination and filtering must keep the interface usable over a large event history.

## Test Focus

- Filter usability: confirm supported filters return the expected billing records quickly and correctly.
- Permission boundaries: verify operators see only records within their finance-role scope.
- Partial-data rendering: ensure a failed source does not blank the entire workspace.
- Status clarity: ensure paid, failed, refunded, and pending states are never ambiguous.

## Developer Notes

- Keep finance data presentation human-readable rather than provider-raw where possible, translating provider statuses into product-friendly states.
- Reuse internal operations shell patterns for consistency, so finance operators get a familiar frame across tools.
