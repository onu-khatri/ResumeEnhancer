# Supporting Information — Cover Letter Draft Model And Resume-Linked Creation Service

## Proposed APIs

- `POST /cover-letters`
- `POST /cover-letters/from-resume`
- `GET /cover-letters/{id}`
- `PATCH /cover-letters/{id}`

## Example Payloads

{

  "templateId": "cl_tpl_01",
  "languageCode": "en"

## Proposed Entities

- `CoverLetter`
- `CoverLetterSection`
- `CoverLetterBodyItem`
- `Resume`
- `TemplateVersion`
- `AuditLog`

## Suggested Technical Controls

- Resume-link ownership validation (reject if user doesn't own the linked resume)
- Independent cover-letter versioning (own version counter, separate from linked resume)
- Template/style compatibility checks (reject if cover-letter template doesn't support the selected style)
- Prefill is one-time at creation; subsequent PATCH operations do not re-sync with the resume

## Edge Cases

- Resume deleted after cover letter was created from it → `linkedResumeId` remains but the link is marked broken; cover letter remains independently editable
- Style mismatch between selected resume and cover-letter template → backend suggests the matching template but allows user override
- Prefill context only partially available (resume has no header data) → prefill what exists, leave remaining fields empty
- User creates multiple cover letters from the same resume → each is independent; no cross-sync
- Cover letter duplicated for multiple applications → standard document duplication applies; new cover letter has no linkedResumeId unless user explicitly links

## Test Focus

- Resume-link authorization (ownership, deleted resume, cross-user access)
- Independent editing after linked start (editing a section doesn't re-prefill from resume)
- Create-from-resume retry safety (idempotency)
- Template matching logic (paired template auto-suggested)

## Developer Notes

- Keep cover-letter document lifecycle parallel to resume lifecycle where possible to simplify workspace logic — both share CRUD, versioning, and export patterns.
- Preserve `linkedResumeId` as contextual metadata for analytics and user continuity, but do not force hard sync. After initial creation, the cover letter's content is independent.
- If AI cover-letter generation is supported, it follows the same `POST /ai/generate` contract as resume AI but with `actionType: "generate_cover_letter"` and context drawn from the linked resume + optional job description.
