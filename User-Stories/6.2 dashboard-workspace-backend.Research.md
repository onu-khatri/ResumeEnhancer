# Research — Saved Documents Index And Workspace Management APIs

## Research Basis

Public competitor evidence suggests document persistence and multi-document management are expected behaviors, even when the exact dashboard UI is not fully exposed in every product. That means the backend must explicitly support a workspace model instead of forcing each feature surface to behave like a standalone tool.

## Requirement Interpretation

- The platform needs a document-summary layer separate from document-content editing payloads. Novorésumé's "My Documents" help article describes a management view with tags and views, which is a list-oriented surface distinct from the editor itself.
- Saved-document management is essential for retention and tailoring workflows. Novorésumé explicitly highlights multiple resume versions and saved progress, showing users expect to maintain several documents over time.
- Duplicate actions are business-critical because they support job-specific resume variations. Resume Now's support guidance implies users tailor resumes per application, making reliable duplication a core workflow rather than a nice-to-have.

## Risks If Under-Specified

- Workspace performance suffers if list screens load full builder payloads. Without a summary layer, the "My Documents" style view Novorésumé documents would slow to a crawl as libraries grow.
- Duplicate/tailor workflows become awkward or error-prone. If duplication is not first-class, users resort to manual re-creation, undermining the multi-version tailoring competitors support.
- Support diagnosis becomes harder if document lifecycle states are not modeled clearly. Resume Now's contact/support flows imply support staff need to reconstruct document history, which requires clear lifecycle and lineage states.

## Recommended Backend Interpretation

- Model workspace APIs as lightweight, list-oriented, and ownership-safe. This mirrors the fast, private "My Documents" experience Novorésumé documents.
- Keep duplication lineage available internally even if not shown prominently in UI. Lineage supports tailoring traceability and future audit without cluttering the workspace.
- Treat resume and cover-letter management as one document-workspace family where possible. Both document types share list, rename, duplicate, and archive behavior, so a unified summary surface reduces duplicated backend work.
