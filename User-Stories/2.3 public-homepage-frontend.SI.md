# Supporting Information - Public Resume Enhancer Homepage And Builder Entry

## Current Implementation Context

- `application/WebSolution/websolution.client/src/app/router.tsx` uses `HomeGate` to redirect unauthenticated `/` to `/login` and authenticated `/` to `/app/resume/dashboard`.
- `application/WebSolution/websolution.client/src/app/route-context.ts` already distinguishes public and authenticated route shells. The homepage should add a public context.
- `application/WebSolution/websolution.client/src/pages/login-page.tsx` is the current public page and contains temporary local-session behavior; that behavior is not the homepage or upload contract.
- `IMP-FE-001` starts after authentication and owns upload, parse progress, review, and builder entry. `ATS-FE-001` owns live analysis and job-match reports after a saved resume exists.

## Representative Preview Rules

- Labels such as "Example analysis", "Sample improvement", or equivalent must distinguish representative content from live user output.
- Sample score values, keyword counts, and insight chips are visual examples only. They are not benchmark claims or expected user outcomes.
- Before/after bullets may use realistic fictional examples but must not be attributed to a real user without consent and approval.
- Company logos, testimonials, ratings, and hiring claims are release-blocked until product/legal supplies a source and approved wording.

## Upload Entry States

| State | Expected behavior |
| --- | --- |
| Default | Explain the next step and expose both file-picker and drag/drop interactions. |
| Keyboard interaction | File picker can be opened with a standard focusable control; the drop zone is not the only mechanism. |
| Unsupported or oversized file | Explain the limit from approved import policy; do not upload or store the file. |
| Selected file, no approved continuation | Explain that sign-in/start is required before secure upload; clear the selection when leaving the page. |
| Selected file, approved continuation | Preserve only the minimum approved ephemeral state through onboarding; never use URL, analytics, or browser persistence for the file. |
| Authenticated | Route to the workspace or approved import entry rather than rendering a public upload interaction. |

## Visual And Responsive Direction

- Use light or light-gray page surfaces, restrained blue/indigo accent colors, 12-16px card radii, subtle borders/shadows, and a spacious max content width near 1200px.
- Desktop: two-column hero with product preview; compact sticky navbar; multi-column feature and proof layouts where content remains readable.
- Tablet: reduce hero density and stack selected sections without losing the upload entry or primary CTA.
- Mobile: single-column hero, tap-first upload control, collapsed/scrollable navigation as appropriate, readable product previews, and no horizontal page overflow.
- Use a purposeful modern product typeface and avoid generic AI/chatbot motifs. Any motion should reinforce hierarchy, respect reduced-motion preferences, and not delay the primary action.

## Accessibility And Security Focus

- Use semantic `nav`, `main`, `section`, and `footer` landmarks; retain one page-level `h1` and a logical heading sequence.
- Ensure all controls have accessible names, visible focus, keyboard activation, sufficient contrast, and touch-friendly targets.
- Provide text alternatives for meaningful preview content and hide decorative icons/imagery from assistive technology.
- Do not use an arbitrary return URL, untrusted query value, file name, or campaign value to construct navigation or rendered HTML.
- Never expose selected-file information, account data, resume data, or analytics identifiers in public markup, URLs, telemetry, or client persistence.

## Test Focus

- Route test: unauthenticated `/` renders the homepage; authenticated `/` routes to the workspace.
- Navigation test: sticky navigation behavior and all active destinations are internal/implemented; unavailable destinations are not active links.
- Upload-entry test: keyboard/file-picker/drag-drop paths are accessible, invalid files do not upload, and the handoff uses only `homepage` source context.
- Preview test: representative content is labelled and cannot be confused with user-specific results.
- Content guard test: disallow unapproved proof assets/claims from release content or validate their approved source in the content fixture.
- Accessibility test: landmarks, heading order, focus behavior, CTA names, FAQ controls, contrast, and responsive reflow.
- Resilience test: missing optional media and failed telemetry do not prevent start or sign-in navigation.

## Open Product Decisions

- Final launch copy, approved illustrative examples, proof assets, testimonials, logo rights, ratings, and legal/privacy language.
- Canonical supported file formats, maximum file size, and whether PDF/DOCX may be shown in the hero.
- Whether pre-authentication selected-file continuation is permitted, and the required retention/security contract if it is.
- Initial public routes for all navbar/footer destinations and the desired behavior for unavailable items.
- Free/Pro inclusions, pricing presentation, "No credit card required" policy, analytics provider, consent model, campaign attribution, and success measure.
- SEO metadata and rendering strategy for the public homepage.
