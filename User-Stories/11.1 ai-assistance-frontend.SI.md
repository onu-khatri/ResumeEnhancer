## Design Token Guidance

### Typography

- AI panel title and action labels should be clear and concise.
- Suggestion text must remain highly readable since users compare wording quality.
- Usage and helper labels should use subtle utility text styles.

### Color

- AI surfaces can use a subtle differentiated accent treatment, but should still live inside the main design system.
- Suggested-content states should be distinguishable from accepted saved content.
- Moderation and error states should use semantic colors carefully without making AI feel dangerous by default.

### Spacing

- Suggestion cards need enough whitespace to support evaluation.
- Primary actions such as `Replace` and `Insert` should have strong visual separation.
- Prompt input and result areas should not feel compressed, especially on tablet.

## Example Request Payload

```json
{
  "resumeId": "res_123",
  "sectionType": "summary",
  "action": "rewrite",
  "currentText": "Experienced engineer with...",
  "instruction": "Make this stronger for product roles.",
  "jobDescription": "Optional pasted JD text"
}
```

## API And Entity Map

- APIs: `POST /ai/generate`, `POST /ai/rewrite`, `GET /ai/usage`
  - Generation and rewrite are separate endpoints so the UI can clearly track which action was requested and the backend can apply different moderation and prompting rules. The usage endpoint drives the quota meter and paywall gating before a request is even attempted.
- Entities: `AIRequest`, `AIUsage`, `Resume`, `JobDescription`
  - `AIRequest` captures the prompt, target section, and action, `AIUsage` tracks remaining quota, `Resume` provides the source context, and `JobDescription` optionally supplies the target role for tailoring.

## Edge Cases

- Empty or vague prompt
  - A prompt with no meaningful instruction should be rejected or gently clarified rather than sent, so the user receives useful guidance instead of a generic or off-target suggestion.
- User requests AI during autosave conflict
  - If the resume is in a version-conflict state, AI output should not be accepted into a stale draft, and the UI must resolve the conflict before applying suggestions.
- AI returns duplicated bullet points
  - Suggestions that duplicate existing content must be flagged or filtered so the user does not accept redundant text, preserving content quality.
- Usage quota becomes exhausted between open and submit
  - The panel may be open when quota runs out, so the submit must re-check usage and surface the paywall state without losing the user's typed prompt.

## Test Focus

- Quota gating
  - Verify the meter and paywall appear at the correct thresholds and that a request is blocked cleanly when quota is exhausted.
- Retry after timeout
  - Simulate a slow or timed-out generation and confirm a retry works without duplicating side effects or corrupting state.
- Keyboard navigation in suggestion review
  - Confirm suggestion cards and their replace/insert actions are fully reachable and operable by keyboard.
- Original-text preservation before accept
  - Assert the user's original text remains intact until they explicitly accept a replacement, and that cancel restores it.

## Developer Notes

- Treat AI output as draft suggestion content, not canonical saved content until user accepts it.
  - Suggestions exist in a transient state and are only written to the resume on explicit acceptance, so a failed or rejected suggestion never pollutes the document.
- Consider diff or before/after view for rewrite actions where replacement risk is higher.
  - A visual diff lowers the risk of an accidental destructive replacement, letting the user compare wording before committing.

## Professional UI Notes

- Avoid making AI look like a toy feature bolted onto the side of the builder.
- The panel should feel intentional, premium, and editorially useful.
