# Supporting Information — Cover Letter Builder With Resume-Aware Start Flow

## Suggested Screens

- Cover-letter start screen
- Resume-linked cover-letter creation state
- Cover-letter editor
- Matching style/template selection state

## Suggested Components

- Resume selector
- Cover-letter template card
- Letter editor
- Greeting / body / closing section helpers
- Matching-style indicator

## Design Token Guidance

### Typography

- Letter content should read more like business correspondence than resume list content.
- Guidance labels should remain subtle and non-intrusive.

### Color

- Maintain visual continuity with the resume product while allowing the letter surface to feel slightly more narrative and document-like.
- Resume-link context should use a subtle informational style.

### Spacing

- Letter body editing requires generous vertical spacing for readability.
- Resume-link metadata should be visible but not consume the editing focus.

## API And Entity Map

- APIs: `POST /cover-letters`, `GET /cover-letters/{id}`, `PATCH /cover-letters/{id}`, `POST /cover-letters/from-resume`
  - The `from-resume` endpoint performs resume-aware prefill, returning a draft letter seeded with header and context so the user starts with content instead of a blank page. Standard create/read/update endpoints cover manual and subsequent editing.
- Entities: `CoverLetter`, `Resume`, `TemplateVersion`
  - `CoverLetter` is the letter document with its own content structure, while `Resume` provides the linked source context and `TemplateVersion` governs matching style rendering. The letter keeps a reference to the source resume but does not embed a copy of resume sections.

## Edge Cases

- Resume selected for prefill was deleted or archived.
  - Prefill must fail gracefully with an explanation and fall back to manual entry rather than silently producing an empty or broken letter.
- Prefill succeeds partially.
  - Some fields may be empty or incomplete after prefill, so the UI must clearly mark which content was filled and which needs the user's attention.
- User changes linked resume mid-flow.
  - Switching the linked resume must reconcile already-entered content and warn before discarding or overwriting fields the user edited.

## Test Focus

- Resume-linked start behavior
  - Verify choosing a resume seeds the letter correctly and preserves the linked-resume indicator through editing.
- Manual fallback after prefill failure
  - Confirm a failed prefill offers a clean manual path and does not trap the user in a broken state.
- Matching-style continuity
  - Assert the selected letter style stays visually consistent with the linked resume template and updates if the style changes.
- Mobile letter editing usability
  - Verify the letter editor remains comfortable on small screens with accessible controls and readable spacing.

## Developer Notes

- Keep cover-letter data model adjacent to but separate from resume sections.
  - The letter has distinct content semantics (greeting, body, closing) that should not be forced into the resume section schema, so a separate model keeps both domains clean.
- Reuse save-state and workspace shell patterns where they fit naturally.
  - Shared save indicators, autosave, and workspace shells reduce duplication and keep the letter experience consistent with the resume builder.
