Characteristics:

- task-oriented layout

- predictable action placement
- room for context panes and system feedback

## Navigation Behavior Rules

- Primary navigation should remain stable for major authenticated modules. Keeping top-level destinations fixed across screens reduces disorientation and lets users build a reliable mental model of the app.
- Secondary navigation should appear only when it meaningfully reduces clutter. Contextual sub-navigation is introduced only where it genuinely helps, otherwise it adds noise rather than structure.
- Back actions should preserve task context. Returning from a deep flow must restore the previous screen's state (filters, scroll, selections) so users do not lose their place.
- Drawer and modal routes should manage focus correctly and restore focus on close. Focus is moved into the overlay on open and returned to the triggering element on close, keeping keyboard and screen-reader users oriented.

## React Architecture Conventions

- Prefer feature-local hooks for feature orchestration. Business logic lives in hooks or containers co-located with the feature, keeping it out of generic presentational components.
- Keep reusable components as presentational as practical. Shared primitives accept props and render, without importing feature-specific state or API clients, so they stay reusable across modules.
- Avoid placing backend-response transformation logic directly in low-level UI primitives. Mapping and normalization belong in feature modules or utilities, not inside buttons or cards.
- Prefer explicit props and typed status models over hidden global assumptions. Explicit interfaces make component contracts clear and prevent coupling to implicit app-wide state.
- Isolate expensive renders such as previews and charts. Memoization or boundary isolation prevents a typing keystroke from re-rendering an entire document preview.
- Reuse shell and feedback primitives before creating feature-specific duplicates. The shared inventory exists to be reused, and duplication should be a deliberate, justified exception.

## Accessibility Baseline Checklist

- Visible focus states
- keyboard-reachable primary actions
- semantic landmarks for shell regions
- accessible labels for form controls
- screen-reader support for async status changes
- text alternatives for charts and color-coded indicators

## QA Review Checklist

- Does the screen use approved shell layout?
- Does it reuse existing token categories?
- Are empty/loading/error/locked states implemented?
- Is mobile behavior intentional rather than incidental?
- Are shared components reused where appropriate?

## Professional Product Notes

- The goal is not to make every page look identical.
- The goal is to make every page feel intentionally designed by the same product team.
- Builder, analysis, AI, billing, and public pages should all feel related while still optimized for their specific jobs.
