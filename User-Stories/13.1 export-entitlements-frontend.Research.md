# Research — Export Experience And Upgrade Entitlement UX

## Research Basis

Export is where product value becomes real for users and where monetization friction is most sensitive. Both competitors anchor monetization at the export moment but do so differently: Novorésumé uses a "preview premium features, pay to download" pattern; Resume Now uses a "free plain-text, paid PDF/DOCX" ladder. Both patterns confirm that export is the highest-leverage monetization gate.

## Competitive Interpretation

- Both competitors **monetize at export**, confirming export is the right conversion moment, but their approaches differ:
  - Novorésumé: "you can build/preview in premium, but can't download" — trust-preserving, value-visible.
  - Resume Now: "you can download basic format for free, but richer formats are paid" — tangible but more restrictive feel.
- Both competitors communicate what is free and what is paid before the user clicks export — **upfront transparency** avoids "surprise paywall" resentment.
- Novorésumé's "data retained after expiry" policy is a trust signal worth replicating.

## Product Interpretation

- Export and monetization are tightly linked; the export UI must handle both technical readiness and commercial boundaries clearly.
- Four export-blocking states must be visually and textually distinct:
  1. Content not ready (missing sections, validation errors)
  2. Plan doesn't allow this (upgrade required)
  3. Running successfully (in progress)
  4. Failed operationally (generation error — not a plan issue)
- "Preview premium, pay to download" is the most trust-preserving gate and should be evaluated for MVP.
- The free-TXT vs paid-PDF/DOCX ladder is a simpler alternative with less technical risk.
- Post-upgrade continuity (return to export flow after checkout) is critical for conversion.

## Hidden Requirements Inferred

- Export-readiness validation (separate from premium gating).
- Format availability matrix per plan.
- Export job state machine (queued, generating, ready, failed).
- Checkout return-state preservation.
- Artifact lifecycle (temporary download URL, re-generation, expiry).
- Entitlement consistency: the same export rules must apply in builder, dashboard, and any direct-link surface.

## Risks If Under-Specified

- Users may think export failed when the real issue is a plan restriction — frustration and support load spike.
- Checkout-return may drop the user at a landing page instead of returning them to the export flow they were in.
- Inconsistent free/premium rules across surfaces (builder vs. pricing page) erode trust.

## Recommendation To Developers

- Model export as an explicit state machine: format selection → validation → generation → ready / failed / locked.
- Keep entitlement checks consistent between in-product export UI, pricing page, and any API responses.
- Treat upgrade as a temporary branch in the user flow — preserve context and return the user cleanly.

## Open Questions

- "Preview premium, pay to download" or "free format, pay for better format" for MVP?
- Should MVP support PDF first and DOCX second, or both at launch?
- Should the free tier export a watermarked PDF or a plain-text version only?
- What is the artifact download-link expiry policy?
